## 4. Pułapki tej sesji (szczegóły w `LESSONS.md`)

- **L28** — „nietrwałe" vs „za wąskie": `localStorage` przeżywa rebuild
  (origin), ale nie przeżywa nowego telefonu; przy konfiguracji potrzebnej na
  każdym urządzeniu uczestnika w aplikacji bez builda jedynym miejscem na stałą
  jest kod w repo — a wtedy publiczność repo jest częścią modelu zagrożenia.
- **L29** — cache-bust `?v=` w ESM jest częścią identyfikatora modułu: podbicie
  tylko w `index.html`/`app.js` daje DWA egzemplarze modułu; kontrakt tego
  rozjazdu nie łapie. Podbijaj `sed`em po wszystkich `app/*.js` i sprawdź
  `git status` przed `git add`.
- **Git w sandboxie** — `.git` bywa odtwarzany z płytkiego klona (lokalne
  commity znikają z bazy obiektów, drzewo robocze zostaje). Procedura:
  `git fetch origin <gałąź>` → `git reset --mixed FETCH_HEAD` → odtworzenie
  commitów z delty. NIGDY `git add -A` przed tym sprawdzeniem (`ENVIRONMENT` §2).
- **Token GitHub** wygasa w trakcie sesji: `git push`/`gh` odmawiają, ponowienia
  nie pomagają — jedyną drogą jest odświeżenie połączenia przez właściciela
  w Arenie; commity lokalne są bezpieczne.
