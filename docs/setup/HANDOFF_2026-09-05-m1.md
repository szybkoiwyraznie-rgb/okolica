## 2. Jak to uruchomić (bez pytań)

```bash
npm test                 # 177 testów, node --test (bez potoku — LESSONS L5)
npm run check            # szablon promptu: docs/PROTOKOL.md ↔ app/protokol.js
npm run brama            # testy + check (zielone przed każdym commitem)
npm run build            # przepisuje szablon z dokumentu do kodu (po edycji PROTOKOL.md)
npm run serwer           # http://0.0.0.0:8000 — podgląd aplikacji
```

- Zero zależności: `npm install` nie jest potrzebne (ADR 0001). Node ≥ 20.
- Aplikację otwiera się przez **serwer HTTP**, nie `file://` — geolokalizacja
  wymaga secure context (aplikacja pokazuje wtedy baner).
- **Tryb testowy**: `index.html?tryb=test` odblokowuje ręczne współrzędne
  (sandbox Areny i desktop nie mają GPS).
- W sandboxie Areny: `start_process` → `npm run serwer` (albo
  `python3 -m http.server 8000 --bind 0.0.0.0`) w katalogu repo, podgląd pod
  `https://8000-<sandboxId>.e2b.app/?tryb=test`.
- Cache-busting: `?v=m1-1` w `index.html` (CSS + moduł) i w **sześciu**
  importach w `app/app.js` — musi być identyczny wszędzie, pilnuje
  `test/kontrakt.test.js`. Po każdej zmianie `app/*.js` podnieś wersję
  (`AGENTS.md` §7).

## 3. Co umie kod po M1 — i czego NIE umie

**Umie (M0):** pięć ekranów setup → pozycja → stacje → prompt → paczka;
walidacja setupu (K01–K20); odczyt GPS i ręczne współrzędne; zapis/odczyt
konfiguracji (`okolica:konfig`, schemat `konfig/1`) i motywu; stacje w trybie
**uproszczonym** (pierścień 0,65–0,85 R, deterministycznie pod ziarnem) z miarą
sprawiedliwości; prompt PYT v1.0; walidacja paczki (E01–E20), „poprawka dla
modelu", ukrywanie paczki (`app/kodowanie.js`, kontener `TO-paczka/2` —
obfuskacja bez klucza, nie szyfrowanie).

**Umie (M1, ta sesja):**
- pełny **model rozgrywki** jako czyste funkcje: `nowaRozgrywka`,
  `startOdcinka`, `zakonczOdcinek`, `pominStacje`, `zapiszOdpowiedz`,
  `premiaCzasu`, `ktoOdpowiada`, `graczNaStacji`, `pytaniaStacji`, `podglad`,
  `podsumowanie`, `wczytajStan`, `mediana`, `dystansOdcinkaM`;
- **warstwę pozycji** jako czyste funkcje: `fixZPozycji`, `ocenFix`, `dodajFix`,
  `stanDojscia`, `bladGeolokalizacji`, `trasaProsta`, `punktNaTrasie`,
  `fixSymulowany`, `sekwencjaSymulowana`, `watchPozycja`, `komunikatPauzy`,
  `komunikatWznowienia`;
- w `app.js`: watcher GPS przez osłonę (opcje z ADR 0004 pkt 1), pauza
  śledzenia w tle i wznowienie, ostrzeżenia o niedokładności, odmowa przy
  pustych współrzędnych ręcznych.

**Nie umie (świadomie, zgodnie z `ROADMAP`):** **ekranu gry** — model
rozgrywki jest policzony i przetestowany, ale nie ma jeszcze UI, które go
prowadzi (M6); mapy i kafelków (M2); sieci drogowej z Overpass i stacji „tylko
w przestrzeni publicznej" (M4); trwałego zapisu stanu gry (`app/trwalosc.js` —
dziś stan gry żyje tylko w pamięci, a `wczytajStan()` ↔ `JSON.stringify(stan)`
to przetestowana para gotowa do zapisu; w `ROADMAP` trwałość stanu należy do
**M6**, bo jej kryterium brzmi „z zamknięciem przeglądarki (wznowienie)", a
zapis paczki i `modyfikacje[]` do **M5**); odsłaniania pytania przy stacji
w UI (M5/M6); podglądu „tylko dla organizatora" z ręczną edycją paczki (M5);
ekranu „dane i prywatność" (M3); podsumowania graficznego i eksportu (M7);
publikacji na GitHub Pages i CI (M8); repozytorium paczek (M9).

**Uwaga na fakty, które zmieniły znaczenie od M0:** kara za ręczne zgłoszenie
dojścia jest **czasowa** (doliczana do `czasS`, domyślnie 60 s,
`karaRecznaS`), nie punktowa — ADR 0004 pkt 5 + ADR 0014 pkt 6. Stary handoff
mówił o „karze punktowej"; nie przepisuj tego do UI ani do dokumentacji.

## 4. Co dalej (kolejka dla następnej sesji)

Kolejność kamieni jest ustalona w `docs/ROADMAP.md` i agent jej nie przesuwa
(„Zasady prowadzenia roadmapy": zmiana kolejności = decyzja właściciela albo
ADR). **Najwyższy nieukończony kamień to M2.**

1. **M2 — `app/mapa.js`**: renderer SVG (Web Mercator — `projektuj`/`odwroc`,
   `siatkaKafelkow`, `metryNaPiksel`, `dopasujZoomDoPromienia` są już w `geo.js`
   i przetestowane), kafelki raster 256 px z podkładów bez klucza API
   (`ASSETS` §1), pan/zoom/pinch, marker pozycji z kołem dokładności, okrąg
   promienia gry, numerowane pinezki stacji, atrybucja zawsze obecna.
   Kryterium jest **wizualne** (360 px, palec, podkład w live preview) —
   w sandboxie kafelków nie pobierzesz (LESSONS L3), więc sprawdza je
   właściciel w live preview Areny.
2. **M3 — dokończenie ekranu konfiguracji**: setup, walidacja, zapis
   `okolica:konfig`, `watchPosition` z badge'em dokładności i tryb testowy są
   zrobione w M0/M1 (włącznie z symulacją trasy w `pozycja.js` — brakuje jej
   podpięcia do UI). Zostało: ekran „dane i prywatność" (ADR 0013) i kryterium
   „pełna konfiguracja na telefonie bez przewijania" do sprawdzenia na żywo.
3. **M4 — `app/sieci.js`**: Overpass z łańcuchem instancji i cache
   (`okolica:sieci:<geohash6>-<R>`, TTL 30 dni) zgodnie z `ASSETS` §2;
   kryterium sprawiedliwości `udzialOdchylenia ≤ 0,15` jest już mierzone w
   `test/stacje.test.js` dla pierścienia i ma być spełnione dla sieci.
   Największe ryzyko projektu; fixture'y `overpass-*.json` dopiero powstaną.
4. **M5 — pętla pytań, reszta**: podgląd „tylko dla organizatora" z ręczną
   edycją i zapisem `modyfikacje[]` oraz odwrotna geokodacja nazwy miejsca
   (wyłączalna, ADR 0013). Prompt, walidacja E01–E20, „poprawka dla modelu"
   i ukrywanie paczki są z M0. Kryterium wymaga testu właściciela z prawdziwym
   modelem.
5. **M6 — rozgrywka (UI)**: pętla stacji na ekranie gry — UI dla
   `rozgrywka.js` (`podglad()` jest gotowym kontraktem dla warstwy DOM) i dla
   `pozycja.js`, plus `app/trwalosc.js` (wznowienie po zamknięciu przeglądarki
   to kryterium M6).
6. Rozstrzygnąć z właścicielem ADR-y proponowane (§6) — szczególnie **0014**
   i **0015**, bo opisują reguły już zaimplementowane w kodzie: jeśli
   właściciel wybierze inaczej, zmiana dotknie `app/rozgrywka.js` i testów.

**Korekta po poprzednim handoffie:** `HANDOFF_2026-09-05.md` §4 przypisywał
`app/trwalosc.js` do kamienia M5 („zapis i odsłanianie paczki"). W `ROADMAP`
M5 to **pętla pytań**, a trwałość stanu gry należy do M6. Poprzedni handoff
zostaje bez zmian jako zapis tamtej sesji — obowiązuje ten plik.

## 5. Fakty operacyjne, które trzeba znać

- **Każdy commit tej sesji był sprawdzany osobno**: `git add <ścieżki>` jawnie
  (LESSONS L7), a zieloność snapshotu weryfikowana przez
  `git worktree add /home/user/wt-<x> <sha>` + `npm test` w tym katalogu, potem
  `git worktree remove --force`. Przydatne, gdy drzewo robocze ma zmiany z kilku
  etapów naraz. Worktree **poza** katalogiem repo, żeby nie zaśmiecać snapshotu.
- **`node --test` traktuje każdy plik `.js` w `test/` jak plik testowy**, także
  `test/helpers/dom.js` — helper nie ma asercji ani skutków ubocznych na
  poziomie modułu i jest liczony jako jeden „test" (plik). Nie przenoś go poza
  `test/`, tylko zachowaj neutralność.
- **Atrapa DOM nadpisuje globale** (`document`, `window`, `navigator`,
  `localStorage`, `location`, `performance`, `Blob`, `URL`). W Node 22+
  `navigator` ma getter — działa tylko `Object.defineProperty(..., {
  configurable: true, writable: true, value })`.
- **Kilka importów `app.js` w jednym pliku testowym dzieli atrapy**, więc
  nasłuchi z każdego egzemplarza się sumują. Test, który potrzebuje innego
  stanu startowego (`?tryb=test`, śmieci w `localStorage`), zakłada **własną**
  atrapę (`zainstalujDom({...})`) i importuje moduł z innym query.
- **Edycja plików z polskimi znakami**: nowe pliki `write_file`, poprawki
  skryptem `python3` z asercją `t.count(stary) == 1` i fragmentem **skopiowanym
  z pliku**, nie przepisanym (LESSONS L2, L12). Skrypt z listą par przerywa się
  przed zapisem, więc „ok" przy parze nie znaczy „zapisane".
- **GitHub**: push działa; przy `Bad credentials` nie pętlij — commituj lokalnie,
  zapisz fakt i ponów później (autoryzacja wraca sama). Opisu PR **nie da się**
  zmienić przez `gh pr edit --body-file` (klasyczne Projects blokują mutację
  GraphQL) — działa `gh api graphql -F id=<node_id> -F body=@plik -f
  query='mutation($id:ID!,$body:String!){updatePullRequest(input:{pullRequestId:$id,body:$body}){pullRequest{url}}}'`.
- **Sieć w sandboxie**: `curl`/`fetch` na zewnątrz nie działa (LESSONS L3) —
  dane z sieci przez narzędzia agenta (`web_search`, `fetch_page`), a Overpass
  i kafelki testuj w przeglądarce albo na fixture'ach.
- Fixture'y są **syntetyczne** i mają to zapisane w sobie:
  `test/fixtures/paczka-ok.json` (pole `uwagi`: fikcyjne Grabowice) i
  `test/fixtures/trasa-odbicie.json` (pole `uwagi`: zmyślone współrzędne
  i dokładności). Nowy fixture też ma mieć takie zastrzeżenie.

## 6. Rzeczy otwarte — do decyzji właściciela

1. **ADR 0014** (*Proponowana*, ta sesja): punktacja czasu — premia/potrącenie
   ±25% punktów za odpowiedź względem mediany **tempa** odcinków; mediana, nie
   średnia; brak premii przy mniej niż dwóch próbkach; limit odcinka zeruje
   premię, ale nie przerywa gry. Kod i testy już tak działają.
2. **ADR 0015** (*Proponowana*, ta sesja): niekompletna paczka nie blokuje gry
   (ostrzeżenie `BRAK-PYTAN` + stacja bez pytania zamyka się dojściem bez
   punktów); pominąć można tylko odcinek **w drodze** (`G13`); liczniki postępu
   i wyniku liczą tak samo; przedrostki kodów `G`/`P`/`K`/`E` nie kolidują.
3. **ADR 0005** (*Proponowana*): sieć drogowa z Overpass — ile zapytań na grę
   jest akceptowalne i czy tryb uproszczony (pierścień) zostaje na stałe jako
   awaryjny.
4. **ADR 0013** (*Proponowana*): geokodacja nazwy miejsca — Overpass domyślnie,
   Nominatim tylko opt-in (polityka OSMF: 1 żądanie/s, zakaz dla platform
   „no-code").
5. **ADR 0002, 0010** (*Proponowana*): hosting GitHub Pages ze ścieżkami
   względnymi; trwałość `localStorage` + docelowe repozytorium paczek.
