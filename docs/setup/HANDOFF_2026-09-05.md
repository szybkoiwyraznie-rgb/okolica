## 2. Jak to uruchomić (bez pytań)

```bash
npm test                 # 82 testy, node --test (bez potoku — LESSONS L5)
npm run check            # szablon promptu: docs/PROTOKOL.md ↔ app/protokol.js
npm run brama            # testy + check (to, co ma być zielone przed commitem)
npm run build            # przepisuje szablon z dokumentu do kodu (po edycji PROTOKOL.md)
npm run serwer           # http://0.0.0.0:8000 — podgląd aplikacji
```

- Zero zależności: `npm install` nie jest potrzebny (ADR 0001). Node ≥ 20
  (testy), przeglądarka z ES modules + geolokalizacją.
- Aplikację otwiera się przez **serwer HTTP**, nie `file://` — geolokalizacja
  wymaga secure context; aplikacja pokazuje wtedy baner (ADR 0004 pkt 6).
- **Tryb testowy**: `index.html?tryb=test` odblokowuje ręczne współrzędne
  (sandbox Areny i desktop nie mają GPS). Ręczne zgłoszenie dojścia ma karę
  punktową konfigurowaną w setupie.
- W sandboxie Areny: `start_process` → `python3 -m http.server 8000
  --bind 0.0.0.0` w katalogu repo, podgląd pod
  `https://8000-<sandboxId>.e2b.app/?tryb=test`.

## 3. Co umie szkielet (M0) — i czego NIE umie

**Umie:** pięć ekranów w kolejności setup → pozycja → stacje → prompt → paczka;
walidację setupu (K01–K20) z komunikatami po polsku; odczyt GPS
(`watchPosition`) i ręczne współrzędne; zapis/odczyt konfiguracji z
`localStorage` (`okolica:konfig`, schemat `konfig/1`) oraz motywu
(`okolica:motyw`); losowanie stacji w trybie **uproszczonym** (pierścień
0,65–0,85 R, deterministycznie pod ziarnem) z miarą sprawiedliwości;
zbudowanie promptu PYT v1.0 ze wszystkimi podstawieniami, kopiowanie do
schowka i pobieranie jako plik; wklejenie/wczytanie odpowiedzi modelu,
walidację paczki E01–E20, listę usterek, „poprawkę dla modelu" do wklejenia
z powrotem i podsumowanie paczki.

**Umie też (po decyzji właściciela, ADR 0007):** ukrywanie paczki —
`app/kodowanie.js` przekształca zwalidowaną paczkę w kontener `TO-paczka/2`
(XOR ze strumieniem z stałego ziarna + base64url + suma kontrolna FNV-1a),
a ekran wklejania przyjmuje **cztery postacie**: kontener jako obiekt, jako
tekst JSON, sam blob base64url i jawny JSON od modelu. To obfuskacja, nie
szyfrowanie — i tak jest opisana w UI oraz w dokumentacji.

**Nie umie (świadomie, zgodnie z `ROADMAP`):** mapy i kafelków (M2), sieci
drogowej z Overpass i stacji „tylko w przestrzeni publicznej" (M4), rozgrywki
wieloosobowej, pomiaru czasu i punktacji (M6), trwałego zapisu ukrytej paczki
i jej odsłaniania przy stacji (M5/M6 — dziś paczka żyje tylko w pamięci sesji),
podsumowania i eksportu (M7), publikacji na GitHub Pages i CI (M8),
repozytorium paczek (M9).

## 4. Co dalej (kolejka dla następnej sesji)

1. **M1 — `app/rozgrywka.js`**: model stanu gry (kolejka graczy, czasy, punkty,
   kara za ręczne zgłoszenie), czyste funkcje + testy. (`app/kodowanie.js`
   powstało już w M0 — ADR 0007 po decyzji właściciela nie wymaga `WebCrypto`.)
2. **M5 — zapis i odsłanianie paczki**: `app/trwalosc.js` (kontener
   `TO-paczka/2` do `localStorage`, budżet rozmiaru, migracje) i odsłanianie
   pytania **w chwili dojścia** do stacji (ADR 0007 pkt 6).
3. **M2 — `app/mapa.js`**: renderer SVG, kafelki raster 256 px, warstwy własne
   (ADR 0003). Weryfikacja na żywo w przeglądarce, nie w Node (LESSONS L3/L6).
4. **M4 — `app/sieci.js`**: Overpass z łańcuchem instancji i cache
   (`okolica:sieci:<geohash6>-<R>`, TTL 30 dni) — zgodnie z `ASSETS` §2.
5. Rozstrzygnąć z właścicielem ADR-y proponowane (patrz §6) — szczególnie
   **0007** (kod gry jako hasło) i **0009** (współpraca: hot-seat vs wiele
   urządzeń), bo oba zmieniają model danych rozgrywki.

Kryteria akceptacji M1–M4 są wypisane w `docs/ROADMAP.md`; kryterium
sprawiedliwości stacji (`udzialOdchylenia ≤ 0,15`) jest już mierzone w
`test/stacje.test.js` i ma zostać spełnione przez układ oparty na sieci
drogowej w M4.

## 5. Fakty operacyjne, które trzeba znać

- **Commit `3e61917` ma komunikat opisujący etap E1, a zawiera też E2** (rejestr
  ADR) — `git add -A` złapał więcej niż komunikat. Historia była już wypchnięta,
  więc bez poprawiania (zakaz force push). Lekcja **L7**; w tej sesji każdy
  `git add` wyliczał pliki jawnie, a `git status --short` szedł przed commitem.
- **Commit `89a0586` (E5) łączy `tools/` z `app/`** celowo: `package.json`
  (wypchnięty wcześniej, w `a6dcb32`) odwołuje się w skryptach do
  `tools/synchronizuj-szablon.mjs`, więc sam `app/` bez narzędzia zostawiłby
  świeży klon z czerwoną bramą. Reguła: commit ma być samodzielnie zielony
  (AGENTS §2.3), a nie „logicznie jednorodny".
- **Test kontraktowy wymaga istnienia handoffu** (`docs/setup/HANDOFF_*`), więc
  `test/kontrakt.test.js` i ten plik są w jednym commicie — inaczej commit
  z testami byłby czerwony.
- **Agent nie zapisze `.github/workflows/`** (403, LESSONS L4) — receptura CI
  leży w `docs/setup/ci-workflow.yml`; właściciel musi ją przenieść ręcznie
  przy publikacji Pages (M8).
- **GitHub na kilkanaście minut stracił autoryzację** (token `GH_TOKEN` zwracał
  `Bad credentials`, `git push` kończył się `could not read Username`), więc
  commity `89a0586`…`9646df7` wisiały lokalnie. Autoryzacja wróciła sama i
  wszystko wyszło jednym `git push origin arena/01a07282-okolica`
  (`a6dcb32..1a4d378`); opis PR #2 zaktualizowany po wypchnięciu. **Reguła:**
  błąd autoryzacji GitHub nie zatrzymuje pracy — zatrzymuje tylko push i
  aktualizację PR; zapisz to w handoffie i ponów.
- `AME-main.zip` leży nietknięty w korzeniu repo — jego los jest pytaniem do
  właściciela (§6), nie decyzją sesji.
- Fixture `test/fixtures/paczka-ok.json` jest **syntetyczny** (fikcyjne
  Grabowice, oznaczenie „FIXTURE TESTOWY" w polu `uwagi`) i nie zawiera
  prawdziwych danych ani współrzędnych stacji — w paczce PYT współrzędnych
  stacji nie ma w ogóle (protokół §3.1), lista stacji jest własnością sesji gry.

## 6. Rzeczy otwarte — do decyzji właściciela

1. ~~**Podkład mapy domyślny**~~ — **rozstrzygnięte 2026-09-05**: właściciel
   wybrał **OSM Standard**; ADR 0003 zaakceptowany (OpenTopoMap i Esri World
   Imagery zostają warstwami opcjonalnymi).
2. **Sieć drogowa** (ADR 0005): Overpass z trzema instancjami i cache — ile
   zapytań na grę jest akceptowalne, i czy tryb „bez sieci" (pierścień, jak
   w M0) ma zostać jako opcja awaryjna na zawsze.
3. ~~**Kod gry i ochrona pytań**~~ — **rozstrzygnięte 2026-09-05**: właściciel
   wybrał „proste kodowanie bez klucza — nieczytelne na pierwszy rzut oka przy
   kopiowaniu, a nie zabezpieczone przed odszyfrowaniem". ADR 0007 przepisany
   przed akceptacją i zaakceptowany: `app/kodowanie.js`, kontener
   `TO-paczka/2`, `kod gry` zostaje **identyfikatorem rozgrywki** (nie kluczem).
   Prawdziwe szyfrowanie: `BACKLOG` B16.
4. ~~**Współpraca**~~ — **rozstrzygnięte 2026-09-05**: „na razie hot-seat";
   ADR 0009 zaakceptowany, gra na wielu urządzeniach zostaje w `BACKLOG` B1.
5. **Geokodacja nazwy miejsca** (ADR 0013): Overpass (domyślnie) vs Nominatim
   (tylko opt-in, bo polityka OSMF zabrania użycia z platform „no-code" i
   wymaga 1 żądanie/s).
6. **Pozostałe ADR-y proponowane**: 0002 (hosting/ścieżki względne),
   0010 (paczki współdzielone), 0013 (prywatność pozycji).
7. ~~**`AME-main.zip`**~~ — **rozstrzygnięte 2026-09-05**: usunięty z korzenia
   (`git rm`); wzorce organizacyjne są przeniesione do `AGENTS.md`, `LESSONS.md`
   i ADR-ów, a plik zostaje w historii git.
